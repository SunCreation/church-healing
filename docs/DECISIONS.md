# 의사결정 기록 (ADR-lite)

형식: 맥락 → 결정 → 결과/대가. 큰 결정만 기록한다.

## ADR-001. 웹 3D + Three.js (Unity 대신)
- 맥락: "3D로 여러 사람이 들어오는 교회 힐링 앱" — 플랫폼 선택 필요
- 결정: 브라우저 + Three.js. 링크 공유만으로 즉시 입장
- 대가: 네이티브급 그래픽/물리 기대 불가, WebGL 필수
- 상태: 채택

## ADR-002. 빌드 없는 클라이언트 + three.js 로컬 서빙
- 맥락: 초기 속도와 배포 단순성이 우선
- 결정: `/vendor/three` → `node_modules/three/build` 정적 매핑, ES 모듈 직접 로드, 번들러 미사용
- 결과: `npm start` 만으로 실행, 의존성 충돌 최소. 트리쉐이킹 없음(허용)
- 상태: 채택

## ADR-003. JSON 파일 저장소 (초기)
- 맥락: DB 인프라 없이 시작, 게시글/기도 제목 수준의 소규모 쓰기
- 결정: `data/db.json` + 500ms 디바운스/원자적 rename 저장, 시드 데이터 포함
- 결과: 재시작해도 데이터 유지. 동시 쓰기 경쟁·대용량에는 취약 → SQLite 이전 예정 (ISSUES W-004)
- 상태: 채택 (임시)

## ADR-004. 오리지널 저폴리 성전 (복제 금지)
- 맥락: "여의도순복음교회 테마" 요청 + 실존 단체의 브랜드/건축물
- 결정: 십자가·빛·회랑·스테인드글라스 모티프로 **재해석**. 공식 로고/외관/명칭을 UI의 주인공으로 쓰지 않음, 한글 레터링은 일반 성구만
- 상태: 채택

## ADR-005. 비공식 고지 + 공식 채널 링크 병행
- 맥락: 사용자 혼동(공식 앱으로 오인) 방지, 예배 시간 정보는 변할 수 있음
- 결정: 입장 화면/안내 패널/README에 비공식 명시, 공식 홈페이지·유튜브·예배안내 링크 상시 노출
- 상태: 채택

## ADR-006. 예배중계는 「동시화상예배 LIVE」 재생목록 임베드
- 맥락: `youtube.com/embed/live_stream?channel=UCa-36V2wccHkTQ0SUziSn0A` 임베드가 "This video is unavailable" 표시 (생중계 중이 아니거나 임베드 제한)
- 결정: 공식 채널의 예배 라이브 수집 재생목록(list=PLaMcIb0DJ7THbXrf6TR6fbUu6LmyRtc_L)을 `videoseries` 임베드로 교체. 예배 시간엔 생방송, 평시엔 최근 예배
- 검증: 헤드리스 Chrome 스크린샷으로 프레임 로드 확인, 공식 링크는 병행 표기
- 상태: 채택

## ADR-007. 서버는 바운드 클램프만, 위치 권위 없음
- 맥락: 치트 방지 vs 구현 비용
- 결정: 서버는 x/z 실내 클램프와 형식 검증만 수행. 벽 관통 등 정밀 검증은 클라이언트에 위임
- 결과: 소수 인원 힐링 공간에는 충분. 경쟁/랭킹 기능을 만들 경우 재검토
- 상태: 채택

## ADR-008. 개인정보 최소 수집 + 익명 기도
- 맥락: 기도 제목은 민감할 수 있음
- 결정: 로그인 없음, 닉네임만, 기도 제목은 익명 옵션, 묵상 노트는 localStorage 전용(서버 저장 안 함)
- 상태: 채택

## ADR-009. 성경 인용은 짧은 단문 + 출처 표기
- 맥락: 성경 번역 저작권(대한성서공회 개역개정 등)
- 결정: 짧은 구절 12개만 인용, 출처 명기, 본문 전체 재현 금지. 확대 시 퍼블릭 도메인 번역(개역한글 1900년대 아님 주의 — 실제 개역한글은 1938년, 저작권 확인 필요) 재검토 또는 공식 라이선스 확인
- 상태: 채택 (재검토 예정)

## ADR-010. 채팅은 전원 표시 + 말풍선 4.2초
- 맥락: 공간감과 소통 가시성
- 결정: 채팅을 토스트+말풍선 이중 표시. 도배 방지는 길이 제한(200자)으로만
- 결과: 레이트리밋 없음 → ISSUES W-002
