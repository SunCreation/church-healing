# 의사결정 기록 (ADR-lite)

형식: 맥락 → 결정 → 결과/대가. 큰 결정만 기록한다.

## ADR-001. 웹 3D + Three.js (Unity 대신)
- 맥락: "3D로 여러 사람이 들어오는 교회 힐링 앱" — 플랫폼 선택 필요
- 결정: 브라우저 + Three.js. 링크 공유만으로 즉시 입장
- 대가: 네이티브급 그래픽/물리 기대 불가, WebGL 필수
- 상태: 채택

## ADR-002. 빌드 없는 클라이언트 + three.js 로컬 서빙
- 맥락: 초기 속도와 배포 단순성이 우선
- 결정: `/vendor/three` → `node_modules/three/build` 정적 매핑, ES 모듈 직접 로드, 번들러 미사용
- 결과: `npm start` 만으로 실행, 의존성 충돌 최소. 트리쉐이킹 없음(허용)
- 상태: 채택

## ADR-003. JSON 파일 저장소 (초기)
- 맥락: DB 인프라 없이 시작, 게시글/기도 제목 수준의 소규모 쓰기
- 결정: `data/db.json` + 500ms 디바운스/원자적 rename 저장, 시드 데이터 포함
- 결과: 재시작해도 데이터 유지. 동시 쓰기 경쟁·대용량에는 취약
- 상태: **대체됨** → ADR-011

## ADR-004. 오리지널 저폴리 성전 (복제 금지)
- 맥락: "신도교회 테마" 요청 + 실존 단체의 브랜드/건축물
- 결정: 십자가·빛·회랑·스테인드글라스 모티프로 **재해석**. 공식 로고/외관은 복제하지 않음. 교회 이름은 사용자 요청에 따라 테마명으로 표시하되 비공식 고지 유지(ADR-017)
- 상태: 채택

## ADR-005. 비공식 고지 + 공식 채널 링크 병행
- 맥락: 사용자 혼동(공식 앱으로 오인) 방지, 예배 시간 정보는 변할 수 있음
- 결정: 입장 화면/안내 패널/README에 비공식 명시, 공식 홈페이지·유튜브·예배안내 링크 상시 노출
- 상태: 채택

## ADR-006. 예배중계는 공식 채널 임베드 (실시간/최근 영상 전환)
- 맥락: 초기 순복음 테마에서 `live_stream` 임베드가 "video unavailable"을 표시해 재생목록으로 우회했던 이력
- 결정: 신도교회 공식 YouTube 채널(`UC7Ko6OUkjH0gThOqEBFRCNA`)을 기준으로 `live_stream?channel=`(실시간)과 업로드 재생목록(`videoseries?list=UU7...`, 최근 영상)을 탭으로 전환. 두 주소 모두 공식 채널에서 파생
- 결과: 최근 업로드를 기본 표시하고 실시간 버튼으로 수동 전환. 방송 중이 아니거나 임베드가 제한되면 공식 채널에서 확인하도록 안내
- 상태: **대체됨** → ADR-017

## ADR-007. 서버는 바운드 클램프만, 위치 권위 없음
- 맥락: 치트 방지 vs 구현 비용
- 결정: 서버는 x/z 실내 클램프와 형식 검증만 수행. 벽 관통 등 정밀 검증은 클라이언트에 위임
- 결과: 소수 인원 힐링 공간에는 충분. 경쟁/랭킹 기능을 만들 경우 재검토
- 상태: 채택

## ADR-008. 개인정보 최소 수집 + 익명 기도
- 맥락: 기도 제목은 민감할 수 있음
- 결정: 로그인 없음, 닉네임만, 기도 제목은 익명 옵션, 묵상 노트는 localStorage 전용(서버 저장 안 함)
- 상태: 채택

## ADR-009. 성경 인용은 짧은 단문 + 출처 표기
- 맥락: 성경 번역 저작권(대한성서공회 개역개정 등)
- 결정: 짧은 구절 12개만 인용, 출처 명기, 본문 전체 재현 금지. 확대 시 퍼블릭 도메인 번역(개역한글 1900년대 아님 주의 — 실제 개역한글은 1938년, 저작권 확인 필요) 재검토 또는 공식 라이선스 확인
- 상태: 채택 (재검토 예정)

## ADR-011. Neon/Lakebase Postgres, 앱 코드는 pg.Pool (JSON은 폴백)
- 맥락: 배포 환경(Render 무료)의 파일시스템은 임시라 재시작 시 커뮤니티 글이 사라짐
- 결정: `DATABASE_URL`(풀링)이 있으면 Postgres, 없으면 `data/db.json` 폴백. 앱 코드는 Node.js 장기 실행 Express이므로 서버리스 드라이버가 아닌 `pg`(Pool, max 4) 사용. 스키마는 `CREATE TABLE IF NOT EXISTS` + 빈 테이블에만 시드(멱등), `createdAt`은 bigint epoch
- 연결: 앱 트래픽 `-pooler`, 마이그레이션은 direct(`DATABASE_URL_UNPOOLED`). `sslmode` 미설정 시 pg가 `require`를 `verify-full`로 승격하도록 코드에서 정규화
- 결과: 로컬 개발은 `.env.local` 없이도 동작(시드만 저장), 배포는 Neon 영구 저장. 검증: Postgres에서 행 수 합계 확인 후 테스트 행 삭제
- 상태: 채택

## ADR-012. CSP/보안 헤더 + 인메모리 레이트리밋
- 맥락: 공개 URL로 불특정 접속 예정, 채팅/게시판 도배 위험
- 결정: CSP `default-src 'self'` + Google Fonts style + YouTube frame-src만 허용, `X-Content-Type-Options`/`X-Frame-Options`/`Referrer-Policy`/`Permissions-Policy`, `X-Powered-By` 제거, `trust proxy 1` (Render 프록시). 레이트리밋은 단일 인스턴스 기준 메모리 구현(API 600/분, 쓰기 60/분, 게시글 30/분, 촛불 15/분, 채팅 10초 5회)
- 대가: 다중 인스턴스 확장 시 Redis 등 외부 저장소로 이전 필요
- 상태: 채택

## ADR-013. 공식 소식 프록시 + 링크 아웃 (재배포 금지)
- 맥락: “실제로 최신 소식도 넣어줘” 요청, 공식 콘텐츠 저작권/혼동 방지
- 결정: 서버가 공식 소스의 목록을 10분 캐시로 수집해 `date/title/url`만 반환. 클라이언트는 게시판/패널에 노출하고 원문은 공식 페이지로 링크
- 결과: 항상 최신 소식이 반영되고, 텍스트 재배포 범위를 최소화
- 상태: **대체됨** → ADR-018

## ADR-014. 좌석 144개를 클라이언트 권위, WS `pos`에 `seat`/`y` 포함
- 맥락: “개별 지정석 1칸씩 앉기” 요구 + 서버 권위 검증 비용 최소화
- 결정: 좌석 배열(`seats`, 0..143)을 클라이언트가 갖고, 점유 여부는 연결된 세션의 `seat` broadcast로 판별. 서버는 정수 범위/클램프만 검증
- 대가: 서버가 점유를 단독으로 알 수 없고, 동일 세션 재접속 시 좌석이 새로 선점될 수 있음
- 상태: 채택

## ADR-015. 아바타 전체 몸이 시야 방향을 따른다
- 맥락: “각 유저가 바라보는 방향을 볼 수 있게” 요청
- 결정: 아바타 회전을 카메라 yaw + π로 맞춤. 걷는 방향이 아니라 카메라가 바라보는 방향이 아바타 정면. 원격 아바타도 동일하게 보간
- 대가: 움직임 애니메이션과 실제 진행 방향이 어긋나 보일 수 있음
- 상태: 채택

## ADR-016. 앞마당(예배당 외부)을 하나의 씬으로 구성
- 맥락: “예배당 바깥쪽에 게시판” 요청, 별도 페이지로 분리 가능
- 결정: 기존 씬을 확장(z=19 앞에 9m)해 포털 아치/담장/석재 바닥/게시판을 추가하고, 카메라 z 상한만 확장. 실내 경계/충돌체도 확장
- 결과: 씬 하나로 세계관 유지, 별도 로딩/라우팅 없음. 3D 빌딩 방향만 고려하면 됨
- 상태: 채택

## ADR-017. 신도교회 테마로 전면 전환
- 맥락: 사용자가 실제 출석하는 교회가 신도교회라며, 순복음 테마의 모든 콘텐츠를 신도교회 기준으로 교체 요청
- 결정: 앱 이름/입장 화면/HUD/3D 레터링/스크린 문구/안내 패널/공식 링크/예배 시간표/기본 닉네임/문서를 모두 신도교회 기준으로 교체
  - 홈페이지 `https://www.shindoch.org`, YouTube `UC7Ko6OUkjH0gThOqEBFRCNA`
  - 주소 `서울특별시 구로구 구일로2길 45 (구로동)`, 대표전화 `02-869-6747`
  - 예배: 주일낮 1~4부(7:30/9:00/11:00/14:00), 오후 찬양예배 14:00, 새벽 월~금 5:30, 수요 19:30, 금요 21:00
- 결과: 3D 지오메트리는 유지하고 텍스트/데이터/링크만 교체. 비공식 고지는 유지
- 예배 영상: 최근 업로드 기본 + 실시간 버튼 수동 전환. 방송 여부 자동 감지/재생 보장은 하지 않음
- 상태: 채택

## ADR-018. 신도교회 공지사항+주보 이중 소스, 탭형 확대 게시판
- 맥락: 사용자가 “공지사항과 주보 둘 다” 게시판에 구비 요청
- 결정: `/api/news`가 `e0101`(공지사항)과 `e04`(주보) 목록 API를 병렬 수집해 `groups[]`로 반환. 3D 게시판은 좌우 2열(공지 3 + 주보 3), 확대 뷰는 상단 탭으로 분류 전환
- 링크: `https://www.shindoch.org/main/<module>/board/<document_idx>` (공식 문서 뷰 라우트)
- 대가: 공식 사이트의 목록 API 응답 구조에 의존. 구조 변경 시 파서 수정 필요(실패 시 기존 캐시 유지)
- 보호: 공개·열람 가능 문서만 허용, 숫자 ID로 공식 링크 구성. 분류별 마지막 성공 목록/시각을 보존하고 동시 조회를 합침. 실패도 10분 캐시해 원본 요청 폭주 방지
- 상태: 채택

## ADR-019. 휴대폰은 독립 터치 입력 + 두 엄지 조작판
- 맥락: 키보드 없이 휴대폰에서도 예배당 이동·착석·게시판 조작 필요
- 결정: 추가 라이브러리 없이 Pointer Events로 이동/회전/달리기와 화면 드래그를 분리. 키보드 입력과 합성하며, 터치마다 pointer capture로 종료를 보장
- UI: 왼쪽 방향 버튼, 오른쪽 빠르게/문맥 행동. 터치 기기 및 좁은 화면에만 노출하고 기존 남색·금색 스타일 유지
- 안전: 패널·채팅 입력·비표시·방향 전환 시 입력 해제, 앉은 동안 이동/시야 고정. 두 번째 손가락의 탭을 지원하되 합성 click 중복/관통 방지
- 대가: 모바일 키보드/노치/성능은 브라우저별 차이가 있어 실기기 추가 확인 필요. VisualViewport·safe-area와 가로 배치 적용
- 상태: 채택

## ADR-010. 채팅은 전원 표시 + 말풍선 4.2초
- 맥락: 공간감과 소통 가시성
- 결정: 채팅을 토스트+말풍선 이중 표시. 도배 방지는 길이 제한(200자) + 연결당 10초 5회 레이트리밋
- 상태: 채택
